# 端到端实测：把生成的 SQL 灌进真库，逐格比对

本文记录 excel2sql 的**端到端验证方法**与**已知问题清单**，面向两类读者：

- 想自己确认「工具生成的 SQL 真能跑、数据真没坏」的使用者；
- 想复现某个历史问题、或改动后做回归的人。

> 本轮实测的对象是 **0.3.1**（暴露出下文 7 个问题），修复落在 **0.3.2**。
> 逐条命令输出、库侧读回 dump 等完整原始记录**不随仓库分发**，
> 只把「结论 + 最小复现 + 避坑清单」沉淀在这里。

---

## 1. 为什么非要多"灌进真库"这一步

excel2sql 只做一件事：把表格每一行渲染成硬编码 SQL 文本。
文本**长得对不对**靠单元测试就能覆盖，但**能不能被数据库真正接受、数据有没有悄悄变形**，
只有真库说了算。所以本轮走的是这条线：

```
生成夹具 → 生成 SQL → 改写成可执行装载脚本 → 灌进三个库 → 读回 → 与源逐格比对
```

**总体结论**：SQL 渲染与转义**全部通过** —— 标识符转义（`[方括号]]列]`、`` `反引号`列 ``、
`"引号"列`、带空格列名）、字符串转义（单引号 / 注入串 / 反斜杠 / emoji）、GBK 输入、
NULL 与空串语义、多行文本不断行、`insert` 分批严格、51,290 行大表端到端无损、流式写出内存有界。

**问题集中在两处**：表头/列取舍（丢数据）、类型推断（丢类型）。详见 §3。

## 2. 复现方法

### 2.1 环境

| 组件 | 要求 |
|---|---|
| Python | 3.12+，`openpyxl`（造夹具 / 读表校验）、`pandas`（大表数值交叉校验） |
| 数据库 | SQL Server / PostgreSQL / MySQL 各一份（Docker 即可）；**Oracle 本轮未覆盖** |
| 免安装运行 | 若用 Windows embed 版 Python，它带 `.pth` 文件会**忽略 `PYTHONPATH`**，需显式把 `src/` 塞进 `sys.path` 再调 `excel2sql.cli.main` |

### 2.2 六个阶段

| 阶段 | 做什么 | 关键点 |
|---|---|---|
| ① 造夹具 | 生成 xlsx / csv，覆盖纯数字、混类型、空值三态、多行文本、怪表头、转义 emoji、GBK、极端值、空表 | **末尾必须回读校验**：`openpyxl` 表达不了空字符串（`''` 落盘变 `None`），所以「空串 vs 空单元格」只能用 CSV 测 |
| ② 跑用例 | 对每个夹具跑不同方言 × 格式，把 命令 / 退出码 / stdout / stderr / 产物全文 落盘 | 断言要落在**行数 / 列数 / 列名**上 —— 本轮的问题全是"退出码 0 的静默丢数据"，只看退出码抓不住 |
| ③ 改写成装载脚本 | `union` 产物（裸 `SELECT`）包成 `SELECT INTO` / `CREATE TABLE AS`；`insert` 产物把表名换掉 | 产物本身**不建表**，直接执行会漏掉建表步骤 |
| ④ 灌库 | 三个方言各执行一遍 | **`sqlcmd` 必须用 `GO` 分批**，否则一处编译错误会让后面所有语句都不执行 |
| ⑤ 读回 | schema + `COUNT` + 行数据，带 `@@@` 分隔标记 | 控制台工具都会"美化"NULL，必须用显式判据（见 §4） |
| ⑥ 比对 | 与源文件逐格比，另比字节数防截断 | 大表传输后**核对字节数**，避免截断而不自知 |

## 3. 问题清单与最小复现

下面每个问题都给一份**最小 CSV**：粘贴成文件、跑一条命令即可看到现象，不依赖任何私有脚本。
（用 `.csv` 而不是 `.xlsx`，是因为空串语义只有 CSV 表达得出来。）

### 🔴 P0-1 表头行误判 → 静默丢一行

**最小复现**（`b.csv`，表头第 2 列**没有列名**，但下面两列都有数据）：

```csv
行ID,
1,甲
2,乙
```

```bash
excel2sql b.csv -d sqlserver
```

- **修复前（0.3.1）**：退出码 `0`，产物只有 **1 行** —— 它把第一行数据 `1,甲` 当成了表头。
- **修复后（0.3.2）**：正确选中第 1 行做表头，随后被表头规范校验拦下，退出码 **`2`**。
- **继续处理**：`--force` 后得到 **2 行 × 2 列**，空列名补成 `col_2`。

同类还有**纯数字列名**（表头 `装运方式,2024`）：修复前得分 1.75 vs 数据行 3.95，
分差 2.2，单靠"分差阈值"拦不住，靠"被跳过的行不止一个非空格就不跳"这条判据才拦下。

> 根因：打分函数里 `filled` 项 = 非空单元格占比，表头一个有空的就掉 `0.5×0.5=0.25` 分；
> 而"位置越靠前越好"的偏好只有 `0.05/行` —— 数据行轻轻松松反超。

### 🔴 P0-2 表头为空的**尾列**被整列裁掉（连数据一起）

**最小复现**（`g.csv`，第 3 列表头留空、但有数据）：

```csv
行ID,数量,
1,10,111
2,20,222
```

```bash
excel2sql g.csv -d sqlserver
```

- **修复前**：产物 **2 列**，第三列 `111 / 222` 连同列一起消失。
  铁证是：把第 3 列数据删空后产出的文件与它有数据时**逐字节相同**。
- **修复后**：退出码 `2`；`--force` 后 **3 列**，第三列补名 `col_3`，值为 `111`。

> 边界：`--header-row 1` 能修好"纯数字列名"，但**修不好"空列名在末尾"**；
> `--force` 只管表头规范校验，管不了"选哪一行做表头"。

### 🟠 P1-3 CSV 所有列被字符串化（`union` 模式彻底丢类型）

**最小复现**（`n.csv`）：

```csv
数量,金额
2,221.98
```

```bash
excel2sql n.csv -d sqlserver            # 产物：N'2' AS [数量]
excel2sql n.csv -d sqlserver --infer-types   # 产物：2 AS [数量]
```

CSV 没有类型信息，读出来全是 `str`，于是整列字符串化。后果是**三库都算不了数**：

| 库 | 直接对字符串列求和 |
|---|---|
| SQL Server | `Msg 8117: Operand data type nvarchar is invalid for sum operator` |
| PostgreSQL | `function sum(text) does not exist` |
| MySQL | 隐式转换，**反而成功**（结果正确，容易掩盖问题） |

**`--infer-types`**（默认关）只做保守转换：**整列都可解析为数字**才转；
带前导零（`'007'`、`'000123'`）、`NaN`/`inf`、混有非数字的列一律保持文本。

### 🟡 P2-4 产物头部告警对纯数字 CSV 是误报

同一份 `n.csv`，修复前产物头部写「混类型列统一为字符串：数量, 金额」——
但这列里根本没有"混类型"，只是 CSV 天生没有类型信息；而它与用户显式加 `--all-string`
时的文案一字不差，无法区分。0.3.2 起改为**分档说明原因**：

| 分档 | 触发条件 |
|---|---|
| `用户指定 --all-string` | 用户显式要求 |
| `同列混有数字/日期与文本，整列统一为字符串` | 真的混类型 |
| `源数据是文本（CSV 无类型信息）` | CSV 等无类型输入 |

### 🟠 P1-5 MySQL 多行文本列被推成 `varbinary`

**最小复现**（`m.csv`，单元格内含换行）：

```csv
收货地址,说明
"上海市
浦东新区",单行说明
```

```bash
excel2sql m.csv -d mysql
```

产物用 `CONCAT(..., CHAR(10), ...)` 拼换行。但在 **MySQL 里裸 `CHAR(10)` 返回的是二进制串**，
`CONCAT()` 一旦遇到二进制参数结果也是二进制 —— `CREATE TABLE AS` 于是推出
`varbinary` 列、字符集为 NULL、排序按字节走。

**修复**：改用 `CHAR(10 USING utf8mb4)`，列类型恢复正常。SQL Server / Oracle / PostgreSQL
的 `CHAR(10)` / `CHR(10)` 写法实测都正常，**只有 MySQL 需要改**。

### 🟠 P1-6 MySQL 执行端默认 `latin1`（属执行端，文档规避）

`docker exec` 无 TTY 时 MySQL 客户端默认 `latin1`，中文/emoji 会按字节落进列里。
**连接时务必显式指定**：

```bash
mysql --default-character-set=utf8mb4 -uroot <db> < load.sql
```

这不是工具的问题，但会让"灌进去中文变问号"被误判成工具 bug。

### 🟡 P3-7 `union` 产物日期列无类型

`union` 产物就是一堆字面量，数据库反推表结构时日期列会落成 `nvarchar` / `text` / `varchar`。
**这是 `union` 形态的固有代价**（反推表结构本来就丢类型），**正式建表请自己写 `CREATE TABLE`**。

## 4. 复现要避的坑（都是测试方法层面的，不是工具的问题）

1. **`sqlcmd` 必须用 `GO` 分隔批次** —— 否则一处编译错误会让**后面所有语句都不执行**，极易误判成"工具生成的 SQL 有问题"。
2. **`sqlcmd -W` 会把 `NULL` 按列宽截断显示**（显示成 `NUL`），**不能**用于判断 NULL vs 空串；用显式 `COUNT(CASE WHEN ... IS NULL ...)`。
3. **`mysql -B` 会转义反斜杠与换行**（`\` → `\\`）；核对字节请用 `--raw` + `HEX()`。
4. **`psql` 默认把 NULL 显示成空串**，需 `-P null='<<NULL>>'`。
5. **别从「首行字面量」推表结构** —— 会踩 `Msg 515`（字面量列被推成 NOT NULL）+ `Msg 2628`（宽度只够第一行）；
   要类型保真，请按源数据实际类型显式建表。
6. **MySQL 连接务必带 `--default-character-set=utf8mb4`**（见 P1-6）。
7. **大表产物经 `tar | ssh | tar` 传输后要比对字节数**，避免截断而不自知。
8. **容器里执行 SQL 时先把文件拷到宿主机再 `docker exec -i < file`**，别在 `ssh` 里拼嵌套引号。
